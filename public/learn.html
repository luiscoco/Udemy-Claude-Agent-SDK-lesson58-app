01

Package the actual SDK service

Compile TypeScript in a Linux build stage and retain the platform-specific optional CLI dependency. Run the HTTP service and its real SDK subprocess as the node user.

02

Inject private configuration at runtime

Keep the model key out of source and image layers. The lab creates short-lived private env files and separate random service/store tokens; it never displays their values.

03

Move transcripts outside replicas

The SDK mirrors transcript entries to a separate authenticated HTTP store backed by its own Docker volume. The store also maps trusted classroom identities to session IDs.

04

Replace and alternate containers

Resume the same session after replacing a replica or sending the next turn to a different replica. A matching per-tenant working directory lets the external transcript hydrate correctly.

05

Test deployment boundaries

Observe actual non-root IDs, read-only root filesystems, CPU/memory/PID limits, rejected authentication and distinct tenant sessions. These examples expose no agent tools.

06

Handle persistence failures honestly

A mirror_error is a durability failure even when a model answer succeeds. Do not commit a failed transcript mapping. Recover the store with the same volume and verify recall of previously committed turns.
